# Data boundaries and removal

Credentials are entered privately in WordPress and stored encrypted using the site's WordPress salts/OpenSSL. No credential is shipped in this repository or browser widget configuration. Salt changes can make saved values unreadable. The illustrative JSON config is not an import mechanism and contains no key.

After customer chat is enabled, questions and relevant authorized public reference text can be transmitted to the configured model provider. Provider policies, charges and processing are external to this plugin. Store facts must be accurate; public-source eligibility does not make conflicting/demo content true.

Private/draft/password-protected/hidden products, protected account/cart/checkout/wishlist paths, customer/order/session data and sensitive patterns are excluded from automatic reference collection. Third-party restriction plugins need explicit exclusions and site-specific verification; published status alone is not universal authorization. Imports, teaching and conversation-derived drafts have separate review gates.

Optional public-context memory stores bounded reference IDs/fingerprints rather than verbatim messages. Saved Inbox conversation capture is separately enabled/consented and bounded in count, turns, size and age. Cleanup depends on working scheduled jobs/database operations. There is no unlimited saved-chat archive and no guarantee that total hosting storage cannot fill for other reasons.

Update and deactivation preserve configuration/data. **Plugin Delete** removes current-site saved customer conversations, unreviewed chat excerpts and attributable current-site administrator chat sessions. Existing configuration/approved knowledge/structured tickets are retained unless the existing explicit full-delete constant was separately enabled by the owner. Failed deletion stops for retry rather than claiming success. Unattributed legacy temporary caches expire separately. No one-site uninstall should delete another site's index.

Public product/page source content is not an instruction or permission. Orders/downloads remain authenticated/account-owned server-side. The widget navigates to native account Downloads rather than returning signed file URLs. Native hosting, bearer/login policy, delivery and grant lifecycle still require your own store tests.

Uninstall cannot erase provider records, independent hosting backups or every external/browser cache. The release validation uses fictional data and disabled fixture logins; it is not proof of real login, provider, notification or file-hosting behavior.
